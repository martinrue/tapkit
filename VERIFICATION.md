These match Chromium's `HotKeyHandler` → `OnHotKeyEvent` → `NotifyKeyPressed` implementation ([macOS listener](https://raw.githubusercontent.com/chromium/chromium/main/ui/base/accelerators/global_accelerator_listener/global_accelerator_listener_mac.mm), [shared listener](https://raw.githubusercontent.com/chromium/chromium/main/ui/base/accelerators/global_accelerator_listener/global_accelerator_listener.cc)). The diagnostic log ends immediately after hiding the djembe. A queued event for a removed hotkey is the likely trigger; the report does not establish which icon or action was clicked.
- Replace wholesale unregister/register transitions with incremental native registrations. Keep summon IDs and overlapping playing-key IDs stable, update the associated voice action in place, and release only keys no longer needed. Stage new registrations before committing, so conflicts leave existing callbacks and native IDs untouched. Released callback closures cannot dispatch after a later registration reuses their key.
- Run commands that can hide windows, open Settings or switch instruments on the next event-loop turn, after the native shortcut callback returns. Preserve every queued navigation press in order. Voice callbacks still send audio IPC synchronously; no audio-path delay or new dependency was added.
